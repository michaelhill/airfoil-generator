# Airfoil generator (Onshape FeatureScript)

## Goal
An Onshape FeatureScript that generates wings by lofting calculated (not looked-up) NACA airfoil sections.
Target document: https://cad.onshape.com/documents/069d976f6440003531b71da3/w/52bd80eb66c2f92abde3e200/e/70610dff99f07cb1c8c0fe9e
- document `069d976f6440003531b71da3`, workspace `52bd80eb66c2f92abde3e200`
- element `70610dff99f07cb1c8c0fe9e` is the Part Studio (the user's test wing lives there)
- element `cca4ef4401f526448b8ed59c` is the Feature Studio **"Airfoil wing"** holding the deployed code

Original user requirements: span set by the user; airfoil definable at root, tip and any % along the span; per profile chord, camber, thickness, origin %, angle of attack (plus sensible extras); loft all profiles into a solid; standard wingtip treatments including "none"; start with NACA and compare against UIUC airfoils (https://m-selig.ae.illinois.edu/ads/coord_database.html); more airfoil families may come later.

## State: working, deployed, pushed
Everything below is implemented in `airfoil_wing.fs`, verified in Onshape, committed and pushed to `origin/main` (latest `456afc1`). The Feature Studio holds the same code. The user has used it and confirmed the features work.

- **Stations**: each station is a NACA designation (4-digit `MPTT`, 5-digit `LPSTT`: standard 210-250 and reflexed 221-251) plus position %, chord, origin %, angle of attack, sweep offset, vertical offset. "Customize shape" reveals camber / camber position / thickness (or design CL / position index / reflexed) pre-filled from the designation by the editing logic. Seeded with a 2412 root and 0012 tip on creation.
- **More NACA families** (`parseNaca`, kinds 4 / 4M / 5 / 16 / 6 / 6A): 4-digit modified `MPTT-IX` (`fourModifiedCoefficients`), 16-series `16-CTT` (= 4M thickness with I=4, X=0.5 plus a=1.0 mean line), 6-series `6F-CTT` with optional subscript (`63(2)-415`, `63_2-415`, `632-415`, `632415`), 6A-series `6FACTT` (`64A010`), optional `a=0.5`. 6/6A thickness by conformal mapping (`sixThickness`) from naca456's 21-knot epsilon/psi tables (`SIX_EPS/PSI/DEPS/DPSI`, Hermite between knots) times the naca456 `SIX_SCALE` polynomial in t/c; mean lines `sixMeanLine` (a=) and `modifiedSixMeanLine` (6A, a=0.8 modified). Family enum value `NACA6` covers 6/6A/16 (customize: design CL + thickness). Their trailing edge closes by a linear pinch or opens to `MIN_OPEN_GAP` like pasted coordinates.
- **Pasted coordinates**: a station's `Airfoil source` can be `Pasted coordinates (.dat)`: the whole Selig or Lednicer file goes into a text field (`parseCoordinates`: numbers with a decimal point, leading out-of-range ones from the name skipped, Lednicer detected by its two counts; `-.0186` style handled). Normalised to unit chord, resampled with PCHIP onto the same cosine x as the NACA sections (`coordinateSurfaces`), so it blends with NACA stations. Closed TE pinches the gap linearly along x, unless that would make the section cross itself (`needsCloseRamp`, 400-point check; sc2110, a blunt edge whose surfaces spread apart at the end): then the thickness is tapered to zero over the last 10 % about the mean line (`CLOSE_RAMP_START`). A concentrated x^32 pinch was tried first: it did not cross but left a ~3 um sliver and the loft still failed; open TE widens it to at least `MIN_OPEN_GAP` 0.0025. Hidden `label` param (set by editing logic) drives the item label `#label @ #position %`.
- **Wing**: `Taper between stations` Straight (default, one loft per segment, unioned) or Smooth (own shape-preserving PCHIP cubic through the stations for chord/origin/sweep/dihedral/twist, ~8 evenly spaced sections per segment, airfoils blended point-by-point, one loft). Closed or open trailing edge. `Mirror about root plane` (needs first station at 0 %).
- **Large twist**: any segment twisting more than `MAX_TWIST_STEP` (10 deg) gets evenly spaced extra sections (`refineTwist` for Straight, more intervals in `smoothSpecs` for Smooth) with blended airfoils, so the mid-chord shortening stays under cos(5 deg). Specs carry `station: true` for user stations; Straight lofts one multi-section loft per station-to-station segment.
- **Wingtips**: none / rounded / elliptical / raked, built as a separate cap loft unioned to the wing. Options: continue sweep and dihedral at the tip station (default on; uses the exact curve slope when Smooth), extra tip sweep angle, continue chord taper (rounded/elliptical only; ticked on new features, but the defaults map has `false` so wings made before it keep their shape; the cap shape scales the continued chord, floored at 0.2x tip chord), continue twist (default off), extra twist at the end of the tip. Raked caps pivot about the LE, others about the origin point.
- **Readout**: `reportFeatureInfo` message with full span, area, aspect ratio, root/tip chord, taper, mean chord, MAC, LE and quarter-chord sweep, dihedral, volume. Numbers verified, and the user confirmed the message displays in the Onshape UI.

### Verification done (all in Onshape through the MCP)
- Sections vs UIUC (NACA 2412, 4415, 23012, 0015, open TE, ray-probed upper and lower surfaces at 7 chord positions): within 0.0001 chord almost everywhere; worst single point 0.0028 chord at the steep nose of 4415 (sparse UIUC points there). The Python reference (`tools/naca_reference.py`) matches UIUC within about 0.0002 chord.
- Reflexed 5-digit (UIUC has none): constants checked with thin-airfoil theory (CL 0.30, Cm about c/4 ~0 vs -0.013..-0.024 for the standard lines, max camber at 10-25 %); Python reference matches the airfoiltools.com generator exactly for 23112 and 25112 (open TE; `http://airfoiltools.com/airfoil/naca5digit?MNaca5DigitForm[posKey]=15_1&...`, coordinates in the page's `<pre>`); FeatureScript section points match Python to 5 decimals (`reflex` suite).
- Pasted coordinates: Python prototype parses 12 UIUC files (Selig and Lednicer, names with decimals like "MH 32 8.7%") with the line breaks removed; resampling passes through the data exactly, 40-point polyline within 0.0008 chord. FeatureScript matches Python to 5 decimals (`coords` suite: naca2412 Selig, goe387 Lednicer). A wing from UIUC `naca2412.dat` is 1.1 % smaller than the calculated 2412: the section area from the sparse 18-point file (plus closing its 0.0026 TE gap) is 98.9 %, so this is the data, not the code. sc2110 (blunt diverging TE) closed with the thickness ramp: sc2110 -> 0012 1939.3 cm3, sc2110 constant 1839.8, open 1944.7.
- 6/6A/16/4M (`six` suite): vs naca456 samples, thickness within 0.0001 chord (0.0002 for the dense-LE sample; the full 201-point tables would give 0.000001, the 21 knots were chosen to keep the FS file small), mean lines exact, 16-series and 0010-64 exact (naca456's 16-009 sample was really run with I=6, X=0.3; its 67-021 sample at t/c 0.15). vs 38 UIUC files (63..66, 63A/64A, 16-series, 0010-34/64): mostly within 0.0001-0.0002 chord closed TE; single-point outliers in naca63206 (x 0.6) and naca63a210 (x 0.5) look like typos in those files. FS section points match Python to 5 decimals; wings 652-415->64A010 smooth rounded tip 2224.1 cm3, 16-212->0010-64 2142.7, 63A210->66-012 open TE 1899.8.
- Volumes: 2412->0012 wing (200->120 mm chord, 1000 mm span) = 2136 cm3; straight 3-station = 1449.6 cm3; mirror = 2x; open TE, flip, sweep/vertical offsets, angle-of-attack sign (positive = nose up), all tips, NACA5.
- Twist check: a lofted wing's mid-span slice vs a constant wing built from halfway parameters: no uneven twist or flip. A large twist between two stations (30 deg) used to shorten the mid chord by about cos(half the angle) (5.5 mm on 160 mm) because the loft blends corresponding points linearly; with the extra sections (`twiststep` suite) the mid-span slice matches within 0.2 mm. Untwisted volumes unchanged: straight 1449.6, smooth 1253.8.
- Tip tangency (Smooth): LE slope 0.082 just inside the tip station, 0.075 just outside (the curve's end slope); Straight 0.125 both sides.
- Chord taper continuation (`tiptaper`, 200->120 mm, 40 mm tip): chord loss rate inside/outside the tip station: rounded on 0.08/0.08, rounded off 0.08/0, elliptical on 0.08/0.77 (the ellipse closing).

## Files
- `airfoil_wing.fs`: the FeatureScript. Key functions: `buildSpecs` (stations -> section specs, returns `{specs, tipIndex}`), `smoothSpecs` / `pchipSlopes` / `hermite`, `buildHalf` (sketches + lofts + unions for one half), `airfoilSurfaces` (NACA math, with point blending), `parseNaca`, `airfoilWingEditLogic`, `wingStats` / `wingReadout`.
- `tools/dat_reference.py`: Python mirror of the pasted-coordinate parsing/resampling. `python3 -I tools/dat_reference.py <dir of .dat files>` prints format, name, points and resampling error.
- `tools/naca_reference.py`: Python mirror of the airfoil math (all families; reads the 6-series tables straight out of `airfoil_wing.fs`) plus comparisons. `python3 -I tools/naca_reference.py <dir of UIUC .dat files>` (designation from the file name, `uiuc_designation`); `--naca456 <dir of naca456 sample .out files>` compares thickness and mean line with naca456 (download `https://www.pdas.com/packages/naca456.zip`, unzip `samples.zip`; keep it out of the repo). Download files from `https://m-selig.ae.illinois.edu/ads/coord/<name>.dat` (naca2412, naca4412, naca4415, naca23012, naca0010, naca0015; naca0012/naca0009 names 404, `n0012.dat` holds several airfoils). Keep downloads out of the repo.
- `tools/onshape_test_harness.fs` + `tools/make_test_code.py`: Onshape test harness. `python3 -I tools/make_test_code.py <out file> [suite]` joins `airfoil_wing.fs` (main feature un-exported) with the harness, ready to paste into the MCP `test_feature`. Suites: `basic` (default: straight/smooth volumes, mirror, mirror error, seeding), `twist`, `tipsweep`, `readout`, `tiptwist`, `tangent`, `tiptaper`, `twiststep`, `reflex`, `coords`, `six`. Harness stations (`stn`) must carry every station parameter (`source`, `label`, ...) or the direct call fails the precondition.

## How to work (Onshape MCP)
- The Onshape MCP (`https://fs-mcp.labs.onshape.app/mcp`, tools `mcp__Onshape__*`) needs the user to authenticate (`/mcp` -> onshape, then reload). The session cannot do OAuth itself. It has dropped mid-session before. Every call uses the user's Onshape API allocation (tell them).
- Std library version is **3095** (check with `test_featurescript` -> `libraryVersion`).
- Test: paste the code from `make_test_code.py` into `test_feature`; results come back in the `throw regenError(out)` message (keep it under about 280 characters). `test_featurescript` runs a lambda snippet. `search_featurescript_documentation` is weak; you can read std source with `get_featurescript` (e.g. loft.fs: did `12312312345abcabcabcdeff`, wvm `v`, wvmid `e3a9bebd99ad03eab7229c12`, eid `0aef2b1033d14885b0266e73`).
- Deploy: `put_featurescript` (did/wid/eid above) with the complete contents of `airfoil_wing.fs` (it overwrites the whole studio). There is no partial-edit tool, so the whole file is pasted each time.
- Always keep the local file and the Feature Studio identical.
- **`put_featurescript` and `test_feature` do not report precondition-analysis errors; only the Onshape UI does.** After deploying, ask the user to refresh the studio and check it is clean.

## Gotchas learned the hard way
- Std 3095: unquoted keys in the `defineFeature` defaults map (`{ flip : false }`) make the feature vanish ("no features found"). Use quoted keys. `box` and `type` are reserved words. `toUpperCase` does not exist.
- Bounds maps: only the first unit entry may be `[min, default, max]`; the rest must be plain defaults.
- A parameter may be declared only once in the precondition, even in mutually exclusive `if` branches ("Duplicate feature parameter"; the 6-series `designCl` hit this). Put the shared parameter in one branch and nest the rest. `test_feature` does not catch it.
- Preconditions can only call predicates, and predicate/`if` conditions must compare a parameter directly (no computed expressions). That is why each station has a hidden `family` parameter set by the editing logic.
- One `opLoft` through sections that are far apart and then very close overshoots wildly (tip volumes were 20x too big), so the wing and the cap are lofted separately and unioned.
- The kernel's loft end condition `MATCH_TANGENT` (helper `createProfileConditions` in `onshape/std/loft.fs`, passed as `derivativeInfo`) works but its magnitude is hard to calibrate; it overshoots on short caps. Abandoned in favour of the own-curve approach for Smooth.
- The Front plane's normal is -Y, so the span runs toward -Y there; use "Flip span direction" or another plane. `evRaycast` returns only the first hit, so probe from above and from below for upper/lower surfaces.
- AoA is bounded to +-45 deg.
- UIUC .dat files have CRLF line endings; the parser treats `\r` as a separator, but strip it before putting a file into a harness string constant.
- FeatureScript's natural log is `log` (there is no `ln`).
- numpy 2 removed `np.trapz`; use `np.trapezoid`.
- UIUC has no reflexed 5-digit files; airfoiltools.com's NACA 5-digit generator does (coordinates in the page's `<pre>`).

## Conventions / interpretation notes
- "Camber radius" was interpreted as max camber (% chord) + camber position.
- Chord along root plane X, thickness along plane Y, span along plane normal. Origin % is both the stacking point and the rotation pivot (default 25 % = quarter chord).
- The "Customize shape" values replace the designation's values for that station; changing the designation while customizing refills them.
- Git: single `main` branch; commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Only commit or push when the user asks.
